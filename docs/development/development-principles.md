# 开发原则

这些原则是代码审查的约束，不是口号。若改动必须违反其中一项，应先在 Issue 或 ADR 中说明原因、范围和退出方案。

## 1. 先保护阅读，再增加能力

- 不改变宿主网页的正文含义、原始顺序或可复制内容。
- 扩展插入物必须可识别、可移除，关闭后不留下交互残片。
- 不可靠的正文识别宁可停止，也不扩大到整页。

## 2. 明确动作优先于猜测

- 翻译、长期记录、远程分析和高费用操作需要明确入口或授权。
- `on-demand` 是行为契约：不得继续扫描、预取、自动注释或被动计数。
- 不根据停留时间、滚动或少量被动信号推断用户能力。

## 3. 数据最小化是架构要求

- 消息和模型请求只携带完成当前任务所需的有限上下文。
- 默认不保存页面 URL、整页正文或不受限制的句子历史。
- `chrome.storage.local` 用于用户明确保留的状态；会话缓存和临时上下文优先使用 `chrome.storage.session` 或内存。
- 新增存储字段必须说明生命周期、清理路径、无痕窗口行为和迁移方式。
- 日志、错误和诊断不得包含 API Key、访问令牌、完整正文或可还原敏感内容。

## 4. 失败必须诚实且可恢复

- 认证、限流、网络、模型格式和权限错误要保留真实类别，给出可执行提示。
- 不用空结果、旧结果或猜测结果伪装成功。
- 可恢复操作应幂等；部分成功应保留，重试只处理失败部分。
- 数据迁移必须原子化；迁移失败时进入安全的无记忆模式，而不是读写半迁移状态。

## 5. 成本是产品行为的一部分

- 自动路径不得生成用户尚未请求的昂贵详情。
- 额外模型调用、路由判定、整页处理和重试必须在界面或文档中可预期。
- 缓存键应基于稳定、最小化且不含原文的身份；无痕窗口不得留下持久缓存。

## 6. 一个概念只有一个实现入口

- 共享设置规范化、服务定义、设计 token、错误分类和数据 schema 不复制第二份。
- 新调用者复用现有模块和消息契约；改变契约时迁移所有调用者并删除旧路径。
- 避免仅为单个调用点建立抽象；当边界稳定且已有多个消费者时再抽取。

## 7. 浏览器边界显式处理

- Content script、extension page、service worker、offscreen document 和 native connector 是不同信任与生命周期边界。
- 所有跨边界消息都验证来源、字段、长度和允许值。
- 新权限遵循最小权限；新增 `permissions`、`host_permissions` 或 web-accessible resource 必须在 PR 中单独解释。
- Service worker 随时可能挂起，正确性不能依赖未持久化的长生命周期全局状态。

## 8. 可访问性和系统偏好不是附加项

- 键盘、焦点、可读标签、状态播报和颜色对比与视觉验收同等重要。
- 不只靠颜色表达状态；遵守 `prefers-reduced-motion`。
- UI 改动遵循 [`docs/design-system.md`](../design-system.md)，并在真实扩展页面和注入网页中验证。

## 9. 测试行为，不固定实现细节

- 回归测试覆盖用户可观察行为、边界、迁移、优先级和真实错误。
- 不为字段转发、源码文本、内部调用次数或 mock 回声写永久测试。
- Bug 修复优先保留能在修复前失败、修复后通过的最小回归测试。
- 所有 PR 至少运行 `npm run check`；浏览器行为按验证清单补充手动证据。

## 10. 文档与改动同时交付

- 用户可见能力更新 README 或设置内“使用说明”。
- UI 规则变化更新设计系统。
- 权限、数据范围或第三方处理变化更新隐私文档。
- 跨模块或难以回退的决定新增 ADR；重要实现新增开发记录。
