# 开发记录

开发记录保存一次重要实现的上下文和交付证据，不替代 Issue、PR 或 Git 历史。

## 何时需要

满足任一条件时，在实现 PR 中新增记录：

- 同时修改三个以上运行时边界；
- 包含存储迁移、权限调整、连接器协议或发布流程变化；
- 用户可见行为存在难以自动验证的兼容性风险；
- 实现过程否决了看似合理、未来可能被重新提出的方案；
- 修复严重的数据、隐私、费用或内容完整性问题。

普通小修、依赖整理、纯文案和有充分测试覆盖的局部重构不需要开发记录。

## 命名

使用 `YYYY-MM-DD-short-topic.md`。一个记录只对应一个交付主题；后续修正通过新 PR 更新原记录，不复制一份“最终版”。

## 内容要求

从 [`TEMPLATE.md`](TEMPLATE.md) 复制，至少填写：

- 背景和明确目标；
- 不在本次范围内的内容；
- 实现边界和数据影响；
- 风险及回滚方式；
- 自动与手动验证证据；
- 相关 Issue、PR 和 ADR。

不要写逐日工作日志、聊天记录、个人笔记或可由 diff 直接还原的文件列表。
